# ForBirds

Лёгкий форум на **PHP 8.3+ и SQLite**, с премодерацией и локальной SHA-256 PoW-проверкой. Исходные макеты подключены к JSON API: HTML/CSS/JS находятся в `public/`, сервер не генерирует HTML-вставки. Чтение API — GET, изменения — POST.

## Уже работает

- Вход/регистрация/выход, страницы профилей с компактной лентой тем и ответов, свои аватарка и описание, «Мои сообщения».
- Главная с отмеченными постами, все темы, разделы с пятью последними темами/ответами, новости, поиск, страницы ответов. Навигация находится в верхней панели рядом со входом.
- Создание тем и ответов, загрузка/перетаскивание/вставка файлов, удаление из выбора и спойлеры.
- Изображения PNG/GIF/JPEG/WebP в лентах и темах: JPEG-превью до 256×256, просмотр оригинала поверх страницы в пределах окна и отдельное скачивание. Для спойлеров используется исходный `public/static/preview/spolier.png`.
- Встроенное воспроизведение аудиовложений (MP3, FLAC, WAV, OGG/Opus, M4A/AAC и др.) и MP4/WebM без автозапуска, с перемоткой и спойлерами.
- Модерация прямо в лентах и темах: администраторы/модераторы видят ожидающие проверки сообщения и могут подтвердить, снять подтверждение, отклонить или удалить их без перехода в очередь. Отдельная очередь также сохранена.
- Автоподтверждение, баны и назначение модераторов через профиль автора; журнал модерации.
- Создание/редактирование/архивирование разделов, закрытие тем, отметки «Новости»/«На главную».
- Обязательная локальная хэш-проверка **каждой** публикации и серверные интервалы **45 с для анонимов / 30 с для всех аккаунтов**.

Оформление возвращено к исходным макетам до API: адаптивная верхняя панель входа и навигации, место под баннер 600×200, синие заголовки, серые таблицы, боковая колонка, область содержимого и табличная форма публикации. Исходный `general.css` не изменён; в `app.css` оставлены стили функциональных дополнений и адаптация для небольших экранов. API, формы, модерация, PoW и интервалы публикации сохранены. Поскольку исходный `banner.png` отсутствовал в репозитории, вместо сломанной картинки оставлено место-заглушка прежнего размера. Ресурсы библиотек хранятся локально; CDN не используются.

## Требования

- PHP **8.3+**: `pdo_sqlite`, `fileinfo`, `mbstring`, `ctype`, `session`, `zlib`, **`gd`** (JPEG/PNG/GIF/WebP).
- SQLite 3.25+ (обычно входит в PHP); отдельный сервер БД не нужен.
- Современный браузер с JavaScript и Web Worker. Хэш-вычисления работают и на локальном HTTP без Web Crypto.
- Python 3.10+ — для HTTP-тестов. Node.js 22+ — для JS/браузерных тестов, **не для работы форума**.

Нет сторонних PHP-зависимостей, Composer необязателен. `composer.json` описывает требования.

## Запуск / обновление

Из корня репозитория:

```sh
php bin/console.php install
# На уже установленном форуме после обновления:
php bin/console.php migrate

php bin/console.php create-admin admin
# Пароль через stdin (12–72 байта), не аргумент командной строки.

# Только для локальной разработки по HTTP:
FORBIRDS_SECURE_COOKIE=0 php \
  -d upload_max_filesize=5M -d post_max_size=21M -d max_file_uploads=20 \
  -S 0.0.0.0:8080 -t public public/router.php
```

Откройте `http://<ваш-хост>:8080/`, войдите созданным администратором и добавьте первый раздел на странице «Создать тему». Затем можно публиковать. Стандартных паролей, публичной установки и автоматического назначения администратора нет.

При обычном stdin ввод может отображаться на экране. В Bash можно использовать:

```sh
read -rs -p 'Пароль: ' PASSWORD; echo
printf '%s\n' "$PASSWORD" | php bin/console.php create-admin admin
unset PASSWORD
```

`install`/`migrate` идемпотентны. Новые версии схемы — отдельные SQL-файлы в `database/migrations/`. Для профилей добавлены `003_profiles.sql` (описание и аватарка) и `004_profile_flags.sql` (выбранный флаг); **выполните миграцию**, не удаляя старую базу.

## Проверка сообщений без отдельной страницы модерации

У администратора и модератора главная автоматически показывает темы **из всех разделов**, а не только отмеченные «На главную», включая ожидающие проверки. В начале списка — непроверенные темы, затем темы с непроверенными ответами. В разделах и поиске персонал тоже видит `pending`; у таких сообщений есть явная пометка и кнопки модерации прямо на карточке. У счётчика ответов видно, сколько из них на проверке. Сами непроверенные ответы отображаются внутри темы с теми же кнопками.

Для гостей, обычных и доверенных пользователей правила публичных лент не изменились: только одобренное содержимое, а на главной — только отмеченные для неё темы. Свои ожидающие сообщения автор аккаунта по-прежнему видит в «Моих сообщениях» и по ID. Права проверяются сервером на каждом запросе, поэтому снятие роли/бан закрывают расширенную выдачу даже в уже открытой сессии. Отклонённые и удалённые темы не добавляются в обычные ленты; отдельная очередь и журнал модерации остаются доступны персоналу.

## Страницы пользователей

Откройте «Моя страница» в навигации или нажмите своё имя в шапке. Имя автора любого поста ведёт на `/profile.html?id=USER_ID`. На странице есть аватарка, роль, дата регистрации, описание и компактная таблица тем/ответов — в стиле «Обновлений», новые сверху. Ссылки на ответы открывают нужную страницу темы и само сообщение; список профиля разбит на страницы по 20 строк.

В своём профиле можно изменить описание (до 4000 байт UTF-8), загрузить или удалить аватарку. Принимаются JPEG, PNG, GIF и WebP до **2 МиБ**. PHP проверяет содержимое и размеры изображения, затем сохраняет только статичный JPEG до 256×256 без метаданных; исходный файл не хранится. Готовые аватарки хранятся отдельно от кэша вложений, в приватном `storage/avatars/`. Новая аватарка показывается и у уже опубликованных сообщений. Смена аватарки удаляет прежний файл; удаление возвращает стандартную картинку. Профили и аватарки публичны, описание выводится как обычный текст, без HTML.

Чужие ожидающие/отклонённые/удалённые сообщения обычным посетителям не выдаются. Свои ожидающие видны в своём профиле, если доступна исходная тема. Скрытый исходный пост скрывает и ответы в профиле. Персонал видит все статусы; прежние действия доверия/бана/роли находятся под кнопкой «Права / бан пользователя». Полный список своих статусов по-прежнему доступен в «Моих сообщениях». Редактировать профиль может только сам вошедший незаблокированный пользователь; нужны сессия и CSRF, PoW и интервал постинга для изменения профиля не требуются.

**Обновление существующего форума:** сначала сделайте резервную копию базы и выполните `php bin/console.php migrate`. Миграция сохраняет пользователей, пароли, роли и сообщения. Загружайте `profile.html`, обновлённый `app.js`, HTML-страницы навигации и серверные файлы вместе.

### Флаги пользователей

В своём профиле можно выбрать флаг с предпросмотром или «Без флага». Он отображается в профиле и у всех сообщений автора, включая старые. Это добровольный выбор пользователя, не геолокация по IP.

Каталог автоматически сканирует **`public/flags/`** при запросе. Добавьте туда PNG, GIF, JPEG или WebP — после обновления страницы картинка появится в списке без регистрации в коде/БД. Файлы должны лежать непосредственно в папке; вложенные папки, симлинки и файлы, не являющиеся поддерживаемыми изображениями, пропускаются. Имя без расширения: 1–64 латинских буквы, цифры, `_` или `-`, первый символ — буква/цифра. Регистр расширения не важен (`RU.png` и `RU.PNG` поддерживаются).

Человекочитаемые названия хранятся в **`public/flags/flags.json`**, UTF-8:

```json
{
  "RU": "Россия",
  "DE": "Германия",
  "ru": "Россия"
}
```

Ключ — точное имя файла **без расширения**, с учётом регистра: `RU` для `RU.png`, `ru` для существующего `ru.gif`. Если ключа нет, значение не является непустой строкой, JSON отсутствует или повреждён, отображается исходное имя без расширения, например `RU`. Запись в JSON сама по себе не добавляет отсутствующую картинку в список. Имена/описания выводятся как текст, без HTML.

Если выбранную картинку удалить, флаг перестанет отображаться и исчезнет из выбора, без сломанной картинки. При возвращении файла с тем же именем сохранённый выбор снова работает. Для сохранения выбора нужна миграция `004_profile_flags.sql` через `php bin/console.php migrate`.

## Превью и изображения

Превью создаются при загрузке через PHP GD: JPEG, без увеличения маленьких картинок, с сохранением пропорций и границей **256×256 px**. Прозрачность при переводе в JPEG заполняется белым. У GIF берётся первый кадр только для превью; оригинал, в том числе анимация, сохраняется побайтно. Нажатие на превью открывает оригинал в модальном просмотрщике поверх сайта, без новой вкладки. Изображение сохраняет пропорции и помещается в окно, в том числе на телефоне. Закрытие — кнопкой, Escape или нажатием на затемнённый фон; фокус возвращается к превью. Анимация GIF сохраняется. В просмотрщике и возле вложения есть ссылка скачивания.

У изображений под спойлером вместо настоящего превью показывается **неизменённый** `public/static/preview/spolier.png` (именно `preview`, как в исходном макете). Пока пользователь не нажал на него, браузер не загружает реальное превью или оригинал. Сам спойлер — визуальная пометка, не дополнительное право доступа к одобренному файлу.

Файлы превью находятся в приватном `storage/previews/`, а не в `public/`. Доступ к `/api/attachments/{id}/preview`, `/view` и `/download` каждый раз проверяется по сообщению и исходному посту темы; все ответы `no-store`. Для старых загрузок или потерянного кэша превью автоматически создаются при первом разрешённом запросе. Повторно загружать изображения и менять схему БД **не нужно**. Директория создаётся автоматически; CLI `install`/`migrate` также её подготавливают.

**Windows:** в используемом `php.ini` раскомментируйте `extension=gd`, проверьте `php -m` и перезапустите PHP-сервер. Без GD новые изображения вернут понятную ошибку `image_processing_unavailable`, а не будут приняты без превью. GD также необходим для проверки перцептивных запретов и ленивой индексации старых изображений. Доступность декодеров JPEG/PNG/GIF/WebP можно проверить через `php -r "print_r(gd_info());"`.

Предельные габариты — 12000 px на сторону и 40 млн пикселей, но дополнительно действует бюджет памяти PHP: слишком большое для текущего `memory_limit` изображение отклоняется с `413` до декодирования. Повреждённое изображение отклоняется с `422`; сообщение, файлы, решение PoW и таймер публикации откатываются вместе.

## Видео и последние сообщения разделов

Видео загружаются как обычные вложения через выбор, перетаскивание или вставку файлов. Поддержаны **MP4 и WebM** с проверкой MIME и расширения. Плеер находится прямо в сообщении: управление, пауза, перемотка и полноэкранный режим — средствами браузера. Нет автозапуска и предварительной загрузки; видео под спойлером даже не получает `src`, пока его не раскроют. Рядом остаётся скачивание оригинала. Если кодек не поддерживается браузером, можно скачать файл; сервер не перекодирует видео, FFmpeg для работы форума **не требуется**.

Лимиты не изменены: **5 МиБ на файл, 20 МиБ суммарно, до 10 файлов**. Каждый запрос к оригиналу, включая `Range` для перемотки и `HEAD`, проверяет видимость сообщения и исходного поста темы. Передача файла идёт частями, с `no-store`; прямого публичного доступа к `storage/uploads/` нет.

В боковой панели у каждого раздела — до **пяти последних сообщений**, включая темы и ответы, новые ID первыми. Краткие ссылки ведут на нужную страницу темы и якорь ответа. Обычным посетителям выдаются только одобренные сообщения в одобренных темах; персоналу также видны ожидающие проверки с явной пометкой. Отклонённые/удалённые сообщения и ответы в скрытой теме не появляются в этом блоке. Список обновляется при загрузке страницы, отправке ответа и встроенной модерации.

Для этих изменений новая миграция не нужна: используются существующие сообщения и вложения. Обновите HTML, CSS, JS и PHP-файлы вместе, чтобы сервер поддерживал видео и выдавал актуальную CSP.

## Публикация и локальная проверка

1. Анонимы и обычные пользователи отправляют сообщения в `pending`.
2. Пользователи с автоподтверждением, модераторы и администраторы сразу получают `approved`.
3. Модератор/администратор выдаёт и отзывает автоподтверждение. Старую очередь это не меняет.
4. **Ни одна роль не освобождается от PoW и интервала публикации.** Темы и ответы используют общий интервал: 45 с между успешными публикациями анонима, 30 с для аккаунта.
5. Анонимный интервал привязан к HMAC IP, пользовательский — к ID аккаунта, не к cookie. Обновление страницы, новые сессии того же аккаунта или новая анонимная cookie не сбрасывают активный лимит. IP берётся только из `REMOTE_ADDR`.
6. После ожидания пользователь нажимает «Вычислить проверку». Worker подбирает nonce: SHA-256 от `prefix:nonce` должен начинаться с заданного количества нулевых **битов**. Браузер не зависает; вычисление можно отменить. Никаких запросов к Cloudflare/Google/сторонним сервисам.
7. Сервер проверяет решение, срок (5 минут), привязку к сессии/автору и однократность. Задача должна быть выдана после окончания предыдущего интервала; нельзя запасти задачи в других вкладках/сессиях до предыдущего поста. Новая задача заменяет предыдущую в той же сессии.
8. Проверка/занятие интервала/создание темы и сообщения выполняются в одной транзакции с write-lock. Ошибка валидации/раздела не сжигает корректное решение и не запускает интервал. Интервал начинается только после принятой публикации, включая ожидающую модерации.

Сложность по умолчанию **18 бит** (~262 тыс. попыток в среднем, не гарантированное время). `FORBIRDS_POW_DIFFICULTY` задаёт 8–24 бита; 8 предназначено для быстрых тестов, для публичного сервера начинайте с 18 и измеряйте на слабых устройствах. Worker останавливается после 120 с вычислений или истечения задачи. Изменение сложности не меняет 45/30 с на сервере.

**Это не настоящий Cloudflare Turnstile и не доказательство человечности.** Боты тоже умеют решать PoW; GPU и распределённые IP/аккаунты снижают его эффективность. Вычисления расходуют батарею, а анонимы за одним NAT разделяют 45-секундный лимит. Самостоятельная регистрация новых аккаунтов не предотвращает обход пользовательского интервала; для более жёсткой защиты нужны ограничения регистрации/сетевые лимиты и наблюдение за злоупотреблениями. PoW дополняет премодерацию и ограничения запросов, а не заменяет их.

## Видимость и безопасность

- До одобрения сообщения/файлы не видны обычным посетителям, не участвуют в их поиске и счётчиках. Снятие одобрения исходного поста скрывает всю тему и её файлы.
- Автор аккаунта может читать собственные ожидающие сообщения; аноним получает только квитанцию с ID/статусом.
- Права читаются из БД на каждом запросе. Баны и отзыв доверия применяются к существующим сессиям.
- Удаление мягкое; содержимое остаётся для модераторов, API-восстановления нет. Физическая очистка файлов — отдельная будущая задача.
- Текст показывается через `textContent`, не `innerHTML`. Пароли хешируются; запросы параметризованы; все POST требуют CSRF-токен.
- Вложения находятся вне document root и скачиваются только после проверки доступа. Только PNG/GIF/JPEG/WebP могут отображаться inline через защищённый image endpoint. Остальные файлы — исключительно скачивание; исполнения HTML/SVG, распаковки архивов или запуска файлов нет.
- CAPTCHA и cookie не дают надёжного аппаратного HWID; скрытого fingerprinting нет.

## Развёртывание

**Document root строго `public/`, не корень репозитория.** Не создавайте alias для `storage/`, `src/`, `database/`, `.git` или `.tools/`.

- Для встраиваемого dev-preview можно задать `FORBIRDS_ALLOW_EMBED=1`: это убирает запрет iframe только у страниц/ресурсов фронтенда. Не включайте на production (по умолчанию `frame-ancestors 'none'`).
- Production: HTTPS + PHP-FPM + Nginx/Apache. `php -S` только для разработки.
- Все URL приложения направляйте в `public/index.php`: он отдаёт только известные HTML/JS/CSS и изображения фронтенда; `/api/…` возвращает JSON. Необходимые CSP-заголовки уже выставляются.
- Apache 2.4: включите `mod_rewrite`, `AllowOverride FileInfo Options`; `public/.htaccess` содержит правило front controller.
- Nginx: направляйте запросы через PHP-FPM в фиксированный `public/index.php`, сохраняя `REQUEST_URI`. Не разрешайте выполнение произвольных PHP-путей. При отдельной отдаче статических ресурсов сохраните эквивалентные allowlist и CSP (`script-src 'self'; worker-src 'self'`).
- Фронтенд и API на **одном origin**, CORS намеренно не включён. В browser-коде относительные URL; localhost другого сервера не требуется.
- Cookie по умолчанию `Secure`, `HttpOnly`, `SameSite=Lax`. На HTTPS не задавайте `FORBIRDS_SECURE_COOKIE=0`.
- Внешнее хранилище: абсолютный `FORBIRDS_STORAGE=/srv/forbirds-data`. CLI и PHP-FPM должны иметь одинаковую настройку/доступ от одного пользователя ОС. `.env` автоматически не загружается.
- PHP-FPM: `upload_max_filesize=5M`, `post_max_size=21M`, `max_file_uploads=20`. API отклоняет >10 файлов; лимит PHP выше, чтобы 11 файлов не обрезались молча. Лимит тела reverse proxy — 21 МиБ; его собственные ошибки могут не быть JSON.
- За reverse proxy настройте доверенные proxy и реальный IP **в веб-сервере**. Приложение игнорирует входящий `X-Forwarded-For`; иначе анонимный лимит легко подделать. Без настройки все посетители за proxy разделят один IP-лимит.
- SQLite/WAL — один сервер, локальная ФС и умеренная нагрузка. Для высокой параллельности нужна миграция на серверную СУБД.
- Дополнительные IP-лимиты: POST 120/мин, публикации 10/мин, задачи PoW 20/мин, вход 10/15 мин, регистрация 5/час. Корзины лимитов используют HMAC. Начиная с миграции 005, IP публикаций отдельно сохраняются для административной модерации с ограниченным доступом и очисткой (см. ниже). Устаревшие задачи удаляются при выдаче новых; корзины публикаций старше суток — при успешной публикации. Access-логи настраиваются отдельно.
- Бэкапы: для работающей SQLite используйте backup API / `sqlite3 ... '.backup ...'`, не копирование одного файла при активном WAL. Сохраняйте `uploads/` и `app.key` (производный кэш `previews/` можно восстановить из оригиналов); для согласованного снимка с файлами остановите запись.

## Языки интерфейса

Русский и английский работают на тех же страницах и URL, без отдельных копий сайта.
При первом посещении появляется окно с кнопками **«Я разговариваю по-русски»** и
**«I speak English»**. Язык браузера не подменяет явный выбор. Предпочтение сохраняется
в `localStorage` (`forbirds-language`); при запрете постоянного хранилища используется
`sessionStorage`, а при запрете обоих — выбор на текущей странице.
В шапке есть переключатель **English / Русский**. Он перезагружает текущий URL и
предупреждает о несохранённых изменениях форм, в том числе выбранных файлах.

Переводятся системные подписи, состояния публикации/модерации, валидация,
ошибки API и локальной хэш-проверки, формат дат и чисел. Посты, имена пользователей,
названия/описания разделов, описания профилей, имена файлов и словарь флагов остаются
исходными. Системные тексты отмечены `data-i18n` или вызываются через `t()`;
английский каталог — `public/en.js`, логика выбора — `public/i18n.js`.
При добавлении системных ошибок API обновляйте `src/Language.php`.
Ошибки самого веб-сервера и встроенные элементы браузера (например, системный
диалог выбора файлов) управляются сервером/браузером, не переводчиком форума.
Миграция БД и внешние сервисы перевода не требуются; CSP остаётся без inline-скриптов.

## Проверки

```sh
find src public bin -name '*.php' -exec php -l {} \;
python3 -m unittest discover -s tests -v
npm test
```

Обычные HTTP-тесты не требуют npm. Они запускают отдельный PHP-сервер и временную базу, не трогая рабочий `storage/`. В них сложность снижена до 8 бит; проверки PoW/интервалов не отключаются. Для обычных функциональных сценариев тестовый helper вручную сдвигает время в БД между постами; отдельные тесты проверяют реальные 45/30 с, повторное использование, срок, привязку и параллельные сессии без такого helper. `PHP_BIN=/path/to/php` меняет PHP-команду.

Для полного сценария в Chromium:

```sh
npm ci  # только dev-зависимость playwright-core, не нужна сайту
npx playwright-core install --with-deps chromium
FORBIRDS_BROWSER=1 python3 -m unittest discover -s tests -v
```

Браузерный тест проверяет реальные формы, Worker, файлы/спойлеры, превью PNG/GIF/JPEG/WebP и просмотр оригиналов внутри окна без предзагрузки скрытых картинок, воспроизведение WebM и закрытие просмотрщика по Escape, премодерацию, поиск, свои/чужие профили, изменение описания и аватарки, компактные сообщения, мобильную вёрстку, выдачу доверия и счётчики 45/30 с; внешних запросов не допускается. CI: HTTP на PHP 8.3/8.4/8.5, полный браузерный сценарий на PHP 8.5 и SHA-256/Worker против `node:crypto`.

## Расширенная модерация и антиспам

После обновления **обязательно выполните миграцию перед запуском HTTP-приложения**
от того же пользователя/с тем же `FORBIRDS_STORAGE`, что и PHP-FPM:

```sh
php bin/console.php migrate
php bin/console.php reindex-media
```

Сделайте согласованный бэкап и на время обслуживания остановите запись.
`reindex-media` строит SHA-256 и отпечатки имеющихся вложений; при обычной выдаче
старые вложения также индексируются лениво. Не удаляйте предыдущие миграции.

### Возможности

- Персонал перемещает целые темы в другой раздел, отдельные ответы — в другую тему.
  ID, автор, вложения и статус модерации сохраняются, действия требуют причину.
- У каждого файла есть кнопки спойлера, скрытия, возврата, безвозвратного удаления
  и добавления в локальный список запрещённых файлов/похожих изображений.
- Скрытие и удаление отзывают доступ по всем прямым URL и вариантам выдачи,
  включая превью, видео, HEAD и Range, даже для персонала. Спойлер — только
  предупреждение, **не** ограничение скачивания.
- `hashban` сохраняет отпечатки, удаляет выбранный оригинал/превью и блокирует
  повторные загрузки и выдачу других совпадений. Снятие запрета возможно в панели;
  удалённый оригинал не восстанавливается. Уже скачанное/закэшированное чужим
  браузером содержимое отозвать невозможно.
- В панели есть архив удалённых/отклонённых сообщений. Ожидающие проверки и
  удалённые посты жёлтые и полупрозрачные, но права просмотра не меняются.
- Подтверждённый ответ поднимает тему; до подтверждения — нет. Чекбокс `sage`
  позволяет ответить без поднятия. Это не отдельный ручной бамп и не обход
  интервалов 45/30 секунд и PoW.

### Ограничения сравнения файлов

Это **локальный denylist, не детектор CSAM** и не замена профильным службам и
процедурам реагирования. Для всех файлов есть точный SHA-256; для изображений —
дополнительно dHash/aHash (первый декодированный кадр) с допуском небольших изменений.
Тесты используют только искусственно сгенерированные легальные изображения и
проверяют в том числе изменение одного пикселя. Универсальной защиты от обхода
нет: обрезка, поворот, наложения, другие кадры и намеренные преобразования могут
обойти сравнение. Для видео и архивов — только сравнение байтов. На однотонных и
похожих картинках возможны ложные совпадения; для больших denylist нужен отдельный
специализированный сервис/индекс и оценка качества, а не линейный перебор.
**Не загружайте незаконные материалы для тестов.**

После запрета при необходимости физически удалите остальные совпадения, включая
совпадающие аватарки (команда необратима; предварительно убедитесь в корректности
запрета и остановите запись):

```sh
php bin/console.php purge-banned-media
```

Отпечатки запретов сохраняются, чтобы удаление оригинала не снимало блокировку.
Права/сроки хранения любых доказательств и действия по сообщениям о незаконном
контенте владелец определяет согласно применимому закону; не распространяйте
материалы через отчёты, репозиторий, тесты или резервные копии.

### IP и идентификаторы

Только администратор может включить в dashboard галочку **«Показывать IP и
идентификаторы»**. Это разрешение в серверной сессии: обычные JSON-ленты не
содержат IP даже у персонала, а отдельный endpoint проверяет роль и галочку.
Показ работает на карточках постов и в списке публикаций профиля; каждый успешный
просмотр записывается в отдельный журнал. До миграции IP не собирались, у старых
постов эти сведения отсутствуют. Модераторы не получают IP.

Поддерживаются временные баны IPv4/IPv6 CIDR, случайного подписанного browser-cookie
и site-local HMAC отпечатка Canvas/WebGL/параметров браузера. Сбор раскрыт в
уведомлении на страницах. Cookie ID можно сбросить, отпечаток — изменить/подделать;
разные люди могут совпасть. Это **не аппаратный HID** и не доказательство одного
и того же человека. Баны по отпечатку применяйте осторожно. Для API и браузеров
без Canvas/WebGL отпечаток необязателен. Смена IP без смены остальных сигналов
не снимает cookie/fingerprint-бан, но гарантировать невозможность обхода нельзя.
Персонал освобождён от этих сетевых/браузерных банов, чтобы сохранить возможность
управления; бан аккаунта действует отдельно.

Никогда не доверяйте произвольному `X-Forwarded-For`. Для настоящих IP за proxy
настройте доверенный real-IP в Nginx. Публикации используют `REMOTE_ADDR`.
Добавьте ежедневный запуск от пользователя приложения (путь/контейнер адаптируйте):

```sh
FORBIRDS_STORAGE=/srv/forbirds-data php /var/www/forbirds/bin/console.php prune-identities
```

Команда очищает IP/CID/HID постов старше 30 дней, журналы просмотра старше 30 дней
и истёкшие баны. **Без расписания автоматической очистки нет.** Cookie живёт
180 дней; активные баны — до заданного срока (1–8760 часов). Отдельно настройте
сроки хранения бэкапов и access-логов. До эксплуатации оцените правовые основания,
уведомление и требования к согласию/приватности в вашей юрисдикции.

### Модерация профилей и отдельных постов (006)

В карточке профиля и в диалоге управления пользователем персоналу доступны:
удаление/хэшбан аватарки, очистка/хэшбан описания и независимые запреты изменения
каждого из этих полей. Модератор управляет обычными участниками, администратор —
также модераторами; профили администраторов защищены. Действия требуют причину
и журналируются. Хэшбан аватарки использует общий список файлов. Хэшбан описания —
точное сравнение нормализованного текста (регистр и пробелы), **не сравнение смысла**.
Есть список запретов описаний со снятием ошибочного запрета. Поля, закрытые
модератором, защищены на сервере, не только отключены в форме.

Карточки постов дополнены отдельными кнопками скрытия/возврата и блокировки/
разблокировки. Оба ограничения скрывают пост от читателей, включая автора;
блокировка дополнительно запрещает подтверждение. При ограничении корня скрывается
вся тема. Поиск, профили, свои сообщения, счётчики, последние сообщения разделов
и доступ к файлам соблюдают ограничения. Персоналу доступна вкладка «Скрытые и
заблокированные посты». Снятие ограничения не подтверждает пост и не восстанавливает
удалённый. Подробности и API — в `docs/API.md`.

При обновлении выполните `php bin/console.php migrate` (после бэкапа и остановки
записи). Миграция 006 добавляет эти возможности и исправляет ссылки на пять
переименованных флагов. Файлы флагов сохранены побайтно; исправлены только имена
для существующего allowlist и добавлены читаемые подписи в словарь.


### Аудиовложения и цветные цитаты

Аудио загружается обычным вложением через выбор, перетаскивание или вставку файла.
Поддержаны **MP3, MP2, FLAC, WAV, OGG/OGA, Opus, M4A/M4B (включая ALAC), AAC,
AIFF/AIF, WMA и WebM-аудио (.weba)**. MIME проверяется серверным fileinfo вместе
с расширением; произвольный octet-stream и HTML, переименованные в MP3, не принимаются.
В сообщении появляется `<audio controls preload="none">` без автозапуска, со
скачиванием оригинала и перемоткой через HTTP Range. Под спойлером плеер создаётся
только после раскрытия и останавливается при сворачивании. Возможность проигрывания
конкретного кодека зависит от браузера/ОС (особенно WMA/AIFF/MP2); сервер не
перекодирует файлы и FFmpeg для работы сайта не нужен. Неподдерживаемый файл можно
скачать по ссылке рядом с плеером. Внешние музыкальные сервисы/iframe не подключаются.
Обычные лимиты 5 МиБ/файл, 20 МиБ/пост, до 10 файлов и вся премодерация,
скрытие, блокировки и хэшбаны действуют и на аудио. Новая миграция не требуется.

В тексте темы или ответа первый символ строки задаёт цвет всей строки:

```text
> зелёная цитата
< оранжевая цитата
^ голубая цитата
```

Маркеры сохраняются видимыми. Символ в середине строки не окрашивает её.
Переносы строк сохраняются, HTML не исполняется и не превращается в разметку.
Окраска применяется к уже существующим сообщениям при просмотре, содержимое БД
не меняется. В кратких списках/поисковых выдержках остаётся обычный текст.

## Tor/I2P: только чтение; реакции (миграция 007)

После согласованного бэкапа БД/медиа и остановки записи выполните `php bin/console.php migrate`
тем же PHP и пользователем, с тем же хранилищем, что и сайт. Для текущего Docker:

```sh
docker exec -u www-data -w /var/www/forbirds forbirds-php php bin/console.php migrate
```

Tor/I2P-классификация использует импортируемые списки IP/CIDR и доверенную серверную
метку выделенного туннельного входа. **Без импорта списка Tor/настройки входа блокировка
не включится сама.** Tor Browser по User-Agent не определяется надёжно; неизвестные
I2P-шлюзы нельзя гарантированно обнаружить. Все POST распознанных клиентов запрещены,
чтение/поиск остаются. При валидной попытке записи браузер и уже вошедший аккаунт
попадают в отдельный постоянный список запрета записи; есть админская страница
снятия с причиной, журнал событий и CLI-восстановление. IP общего Tor-выхода
не превращается в постоянный персональный бан. Списки нужно регулярно обновлять.
Полные команды импорта, настройки nginx/Docker, ограничения и восстановление:
**[docs/NETWORK_ACCESS.md](docs/NETWORK_ACCESS.md)**.

Реакции берутся автоматически из `public/static/reactions`: положите туда, например,
`like.png`, `laugh.gif`, `heart.webp` (до 512×512, 2 МиБ, до 128 изображений).
Включены три базовые иконки: like, heart, laugh; их можно заменить или удалить. Необязательный словарь
`reactions.json`: `{"like":"Нравится","laugh":"Смешно"}`. SVG и символические
ссылки не допускаются. После добавления обновите страницу — регистрация файлов
в БД не требуется. Кнопка «+» под постом открывает выбор всех доступных реакций.
Под постом отображаются только реакции со счётчиком больше нуля; неиспользованные
остаются доступны в выборе. У вошедшего пользователя одна реакция на пост; повторное нажатие
снимает её, другая заменяет. Гости видят счётчики, но не голосуют. Скрытие корня/поста,
бан, закрытая тема, архив раздела и режим только чтения защищены сервером.

## Фалзфлаг администратора и Markdown (миграция 008)

После бэкапа и остановки записи примените миграцию тем же PHP/пользователем и с тем
же хранилищем, что использует сайт. Для текущего Docker:

```sh
docker exec -u www-data -w /var/www/forbirds forbirds-php php bin/console.php migrate
```

В форме темы/ответа **только администратору** доступен флажок «Опубликовать от другого
пользователя»: укажите ID существующего пользователя (из ссылки на его профиль)
и обязательную причину. Перед отправкой показывается подтверждение с именем.
После успешной публикации режим сбрасывается, чтобы случайно не продолжить писать
под чужим именем. Публично используются профиль, имя, роль, аватарка и флаг выбранного
пользователя; пост появляется и в его списках сообщений. Его настройки доверия/бана
не подменяют права реального администратора. CAPTCHA и интервал — реальные админские;
сетевые read-only ограничения сохраняются. Темы и ответы публикуются как админские
действия, сразу подтверждёнными, с обычными правилами бампа/sage.

Реальный администратор, выбранный автор, причина и время фиксируются в отдельном
закрытом журнале в той же транзакции, что и пост. Журнал доступен только
администраторам через ссылку «Закрытый журнал фалзфлага» в панели; модераторский
общий журнал и публичные API не содержат записи о подмене. Удаление поста обычной
модерацией не стирает закрытую запись. Это смена публичной атрибуции, **не сетевой
анонимайзер**: серверные логи, закрытые IP-данные и метаданные вложений остаются.

Markdown применяется к телу тем/ответов (включая старые): заголовки, **жирный**,
*курсив*, ~~зачёркивание~~, списки, ссылки, таблицы, inline-код и fenced-блоки кода.
Цветные строки `>`, `<`, `^` сохраняются с видимыми маркерами; внутри блоков кода
они не окрашиваются. Пользовательский HTML не исполняется, опасные схемы ссылок
блокируются, внешние картинки не загружаются. Вложения и их спойлеры не меняются.
API и БД сохраняют исходный Markdown; заголовки, имена, профили и краткие выдержки
по-прежнему выводятся обычным текстом.

Обновляйте `public/markdown.js`, `app.js`, CSS, формы и PHP одновременно.
`public/markdown.js` — включённый в репозиторий локальный bundle markdown-it;
Node/npm и CDN для работы сервера не нужны. Для изменения/обновления парсера:

```sh
npm ci
npm run build:markdown
npm test
```

Исходник: `frontend/markdown.js`, лицензии: `docs/MARKDOWN_LICENSES.txt`.

## Режим показа и эмодзи в сообщениях

Кнопка **«Режим показа»** в шапке (также **Alt+Shift+M**, в том числе из
модального окна) переключает безопасный для демонстрации интерфейс с перезагрузкой.
Сначала сохраните черновик: переключение может обновить и другие вкладки.
Настройка сохраняется в браузере; отдельный скрипт в `<head>` скрывает приватные
элементы до первого отображения. Если persistent storage недоступно, используется
session storage вкладки; если недоступны оба — переключение не выполняется.

В этом режиме скрыты панели/журналы модерации, ожидающие проверки и ограниченные
посты, IP/идентификаторы, служебные статусы и элементы своего аккаунта. Просмотр
тем, ленты, разделов и публичных профилей идёт с правами гостя; формы публикации,
реакции и прочие действия отключены. Серверные права и сессия не меняются.
Это защита интерфейса от случайного попадания в кадр, **не анонимизация**: публичный
текст, имена авторов, URL в адресной строке, другие программы, инструменты
разработчика и загрузки не скрываются. Перед стримом включите режим и проверьте кадр.

Рядом со справкой по форматированию в формах тем и ответов появился раскрывающийся
выбор **«Эмодзи из реакций»**. Нажатие вставляет `:имя_файла_без_расширения:`
(например, `:like:`) в позицию курсора или вместо выделенного текста. Используется
тот же каталог `public/static/reactions`; коды чувствительны к регистру. Если
несколько файлов имеют одно имя без расширения, выбирается первый в порядке
каталога. В БД/API остаются исходные коды. В теле сообщения они отображаются
локальными картинками; неизвестные коды, экранированное двоеточие, inline-код,
блоки кода и адреса ссылок не заменяются. Удаление картинки из каталога вернёт
отображение кода текстом. Новая миграция БД не требуется.

## Flash через Ruffle и свёрнутые разделы

К темам и ответам можно прикладывать **`.swf`**: FWS (без сжатия) и CWS (zlib).
Обычные лимиты загрузки сохраняются: 5 МиБ на файл, 20 МиБ на сообщение, до 10
файлов. Сервер проверяет заголовок, объявленный размер и границы тегов; размер
после распаковки ограничен **32 МиБ**. ZWS/LZMA не принимается. PHP требуется
расширение `zlib`. Новая миграция БД не нужна.

Вложение запускается только кнопкой **«Запустить Flash»** — до нажатия не
загружаются ни SWF, ни Ruffle. **«Остановить Flash»** удаляет проигрыватель;
сворачивание спойлера тоже останавливает его. Оригинал можно отдельно скачать.
Премодерация, права на исходную тему, скрытие файлов/постов и хэшбаны сохраняются.

Ruffle **0.8.0** поставляется локально в `public/vendor/ruffle/` (примерно 29 МиБ),
без CDN и Adobe Flash-плагина. Запуск происходит в sandboxed iframe **без
allow-same-origin**: Flash не получает доступ к DOM форума, cookie или storage.
Сеть, переходы по URL и JavaScript-мост отключены в Ruffle. Из родительской
страницы в sandbox передаются только уже авторизованно загруженные байты SWF;
URL API, CSRF и сессия не передаются. Разрешение WebAssembly в CSP действует
только на `/flash-player.html`, не на основной странице. CORS `*` включён только
для публичных JS/WASM Ruffle, не для API или вложений.

**Не все Flash-файлы совместимы с Ruffle.** Файлы, требующие внешних ресурсов,
сети, Flash cookies, JavaScript-интеграции или LZMA, могут не работать. Структурная
проверка и sandbox не гарантируют отсутствие ошибок в эмуляторе; обновляйте Ruffle.
Уже загруженный проигрывателем файл не может быть отозван задним числом, но все
последующие запросы проверяют доступ заново.

Для обновления локального runtime: измените точную версию `@ruffle-rs/ruffle`,
выполните `npm ci && npm run vendor:ruffle`, синхронизируйте **точные имена WASM**
в allowlist `src/StaticFiles.php`, тест целостности и закоммитьте runtime с
лицензиями. Не копируйте source maps или весь `node_modules`. В CI проверяется,
что vendoring воспроизводим. На production Node/npm не требуются. Обновляйте PHP,
HTML, JS/CSS и `public/vendor/ruffle` вместе; запросы должны проходить через
`public/index.php`, чтобы сохранить CSP, MIME WASM и CORS для opaque sandbox.

Свёрнутые/раскрытые разделы боковой колонки теперь запоминаются **по ID раздела**
в браузере (`forbirds-section-{id}`). Состояние восстанавливается до добавления
раздела на страницу — после обновления и переходов между страницами. Новые
разделы раскрыты по умолчанию, остальные сохраняют свою настройку независимо.
При запрете localStorage используется sessionStorage, при запрете обоих хранилищ
навигация работает без сохранения между страницами. Это настройка браузера,
а не аккаунта; очистка данных сайта сбрасывает её.
