# ForBirds

Лёгкий форум на **PHP 8.3+ и SQLite**, с премодерацией и локальной SHA-256 PoW-проверкой. Исходные макеты подключены к JSON API: HTML/CSS/JS находятся в `public/`, сервер не генерирует HTML-вставки. Чтение API — GET, изменения — POST.

## Уже работает

- Вход/регистрация/выход, страницы профилей с компактной лентой тем и ответов, свои аватарка и описание, «Мои сообщения».
- Главная с отмеченными постами, все темы, разделы с пятью последними темами/ответами, новости, поиск, страницы ответов. Навигация находится в верхней панели рядом со входом.
- Создание тем и ответов, загрузка/перетаскивание/вставка файлов, удаление из выбора и спойлеры.
- Изображения PNG/GIF/JPEG/WebP в лентах и темах: JPEG-превью до 256×256, просмотр оригинала поверх страницы в пределах окна и отдельное скачивание. Для спойлеров используется исходный `public/static/preview/spolier.png`.
- Встроенное воспроизведение вложений MP4/WebM без автозапуска, с перемоткой и спойлерами.
- Модерация прямо в лентах и темах: администраторы/модераторы видят ожидающие проверки сообщения и могут подтвердить, снять подтверждение, отклонить или удалить их без перехода в очередь. Отдельная очередь также сохранена.
- Автоподтверждение, баны и назначение модераторов через профиль автора; журнал модерации.
- Создание/редактирование/архивирование разделов, закрытие тем, отметки «Новости»/«На главную».
- Обязательная локальная хэш-проверка **каждой** публикации и серверные интервалы **45 с для анонимов / 30 с для всех аккаунтов**.

Оформление возвращено к исходным макетам до API: адаптивная верхняя панель входа и навигации, место под баннер 600×200, синие заголовки, серые таблицы, боковая колонка, область содержимого и табличная форма публикации. Исходный `general.css` не изменён; в `app.css` оставлены стили функциональных дополнений и адаптация для небольших экранов. API, формы, модерация, PoW и интервалы публикации сохранены. Поскольку исходный `banner.png` отсутствовал в репозитории, вместо сломанной картинки оставлено место-заглушка прежнего размера. В интерфейсе нет сторонних библиотек или CDN.

## Требования

- PHP **8.3+**: `pdo_sqlite`, `fileinfo`, `mbstring`, `ctype`, `session`, **`gd`** (JPEG/PNG/GIF/WebP).
- SQLite 3.25+ (обычно входит в PHP); отдельный сервер БД не нужен.
- Современный браузер с JavaScript и Web Worker. Хэш-вычисления работают и на локальном HTTP без Web Crypto.
- Python 3.10+ — для HTTP-тестов. Node.js 22+ — для JS/браузерных тестов, **не для работы форума**.

Нет сторонних PHP-зависимостей, Composer необязателен. `composer.json` описывает требования.

## Запуск / обновление

Из корня репозитория:

```sh
php bin/console.php install
# На уже установленном форуме после обновления:
php bin/console.php migrate

php bin/console.php create-admin admin
# Пароль через stdin (12–72 байта), не аргумент командной строки.

# Только для локальной разработки по HTTP:
FORBIRDS_SECURE_COOKIE=0 php \
  -d upload_max_filesize=5M -d post_max_size=21M -d max_file_uploads=20 \
  -S 0.0.0.0:8080 -t public public/router.php
```

Откройте `http://<ваш-хост>:8080/`, войдите созданным администратором и добавьте первый раздел на странице «Создать тему». Затем можно публиковать. Стандартных паролей, публичной установки и автоматического назначения администратора нет.

При обычном stdin ввод может отображаться на экране. В Bash можно использовать:

```sh
read -rs -p 'Пароль: ' PASSWORD; echo
printf '%s\n' "$PASSWORD" | php bin/console.php create-admin admin
unset PASSWORD
```

`install`/`migrate` идемпотентны. Новые версии схемы — отдельные SQL-файлы в `database/migrations/`. Для профилей добавлены `003_profiles.sql` (описание и аватарка) и `004_profile_flags.sql` (выбранный флаг); **выполните миграцию**, не удаляя старую базу.

  post.html              тема и форма ответа

  sha256.js              SHA-256 без внешних зависимостей

Макеты и их ресурсы **перенесены из корня в `public/`**, старые URL `/index.html`, `/post.html`, `/dashboard.html` сохранены. У темы URL `/post.html?id=THREAD_ID`, раздела — `/index.html?section_id=ID`.

## Проверка сообщений без отдельной страницы модерации

У администратора и модератора главная автоматически показывает темы **из всех разделов**, а не только отмеченные «На главную», включая ожидающие проверки. В начале списка — непроверенные темы, затем темы с непроверенными ответами. В разделах и поиске персонал тоже видит `pending`; у таких сообщений есть явная пометка и кнопки модерации прямо на карточке. У счётчика ответов видно, сколько из них на проверке. Сами непроверенные ответы отображаются внутри темы с теми же кнопками.

Для гостей, обычных и доверенных пользователей правила публичных лент не изменились: только одобренное содержимое, а на главной — только отмеченные для неё темы. Свои ожидающие сообщения автор аккаунта по-прежнему видит в «Моих сообщениях» и по ID. Права проверяются сервером на каждом запросе, поэтому снятие роли/бан закрывают расширенную выдачу даже в уже открытой сессии. Отклонённые и удалённые темы не добавляются в обычные ленты; отдельная очередь и журнал модерации остаются доступны персоналу.

## Страницы пользователей

Откройте «Моя страница» в навигации или нажмите своё имя в шапке. Имя автора любого поста ведёт на `/profile.html?id=USER_ID`. На странице есть аватарка, роль, дата регистрации, описание и компактная таблица тем/ответов — в стиле «Обновлений», новые сверху. Ссылки на ответы открывают нужную страницу темы и само сообщение; список профиля разбит на страницы по 20 строк.

В своём профиле можно изменить описание (до 4000 байт UTF-8), загрузить или удалить аватарку. Принимаются JPEG, PNG, GIF и WebP до **2 МиБ**. PHP проверяет содержимое и размеры изображения, затем сохраняет только статичный JPEG до 256×256 без метаданных; исходный файл не хранится. Готовые аватарки хранятся отдельно от кэша вложений, в приватном `storage/avatars/`. Новая аватарка показывается и у уже опубликованных сообщений. Смена аватарки удаляет прежний файл; удаление возвращает стандартную картинку. Профили и аватарки публичны, описание выводится как обычный текст, без HTML.

Чужие ожидающие/отклонённые/удалённые сообщения обычным посетителям не выдаются. Свои ожидающие видны в своём профиле, если доступна исходная тема. Скрытый исходный пост скрывает и ответы в профиле. Персонал видит все статусы; прежние действия доверия/бана/роли находятся под кнопкой «Права / бан пользователя». Полный список своих статусов по-прежнему доступен в «Моих сообщениях». Редактировать профиль может только сам вошедший незаблокированный пользователь; нужны сессия и CSRF, PoW и интервал постинга для изменения профиля не требуются.

**Обновление существующего форума:** сначала сделайте резервную копию базы и выполните `php bin/console.php migrate`. Миграция сохраняет пользователей, пароли, роли и сообщения. Загружайте `profile.html`, обновлённый `app.js`, HTML-страницы навигации и серверные файлы вместе.

### Флаги пользователей

В своём профиле можно выбрать флаг с предпросмотром или «Без флага». Он отображается в профиле и у всех сообщений автора, включая старые. Это добровольный выбор пользователя, не геолокация по IP.

Каталог автоматически сканирует **`public/flags/`** при запросе. Добавьте туда PNG, GIF, JPEG или WebP — после обновления страницы картинка появится в списке без регистрации в коде/БД. Файлы должны лежать непосредственно в папке; вложенные папки, симлинки и файлы, не являющиеся поддерживаемыми изображениями, пропускаются. Имя без расширения: 1–64 латинских буквы, цифры, `_` или `-`, первый символ — буква/цифра. Регистр расширения не важен (`RU.png` и `RU.PNG` поддерживаются).

Человекочитаемые названия хранятся в **`public/flags/flags.json`**, UTF-8:

```json
{
  "RU": "Россия",
  "DE": "Германия",
  "ru": "Россия"
}
```

Ключ — точное имя файла **без расширения**, с учётом регистра: `RU` для `RU.png`, `ru` для существующего `ru.gif`. Если ключа нет, значение не является непустой строкой, JSON отсутствует или повреждён, отображается исходное имя без расширения, например `RU`. Запись в JSON сама по себе не добавляет отсутствующую картинку в список. Имена/описания выводятся как текст, без HTML.

Если выбранную картинку удалить, флаг перестанет отображаться и исчезнет из выбора, без сломанной картинки. При возвращении файла с тем же именем сохранённый выбор снова работает. Для сохранения выбора нужна миграция `004_profile_flags.sql` через `php bin/console.php migrate`.

## Превью и изображения

Превью создаются при загрузке через PHP GD: JPEG, без увеличения маленьких картинок, с сохранением пропорций и границей **256×256 px**. Прозрачность при переводе в JPEG заполняется белым. У GIF берётся первый кадр только для превью; оригинал, в том числе анимация, сохраняется побайтно. Нажатие на превью открывает оригинал в модальном просмотрщике поверх сайта, без новой вкладки. Изображение сохраняет пропорции и помещается в окно, в том числе на телефоне. Закрытие — кнопкой, Escape или нажатием на затемнённый фон; фокус возвращается к превью. Анимация GIF сохраняется. В просмотрщике и возле вложения есть ссылка скачивания.

У изображений под спойлером вместо настоящего превью показывается **неизменённый** `public/static/preview/spolier.png` (именно `preview`, как в исходном макете). Пока пользователь не нажал на него, браузер не загружает реальное превью или оригинал. Сам спойлер — визуальная пометка, не дополнительное право доступа к одобренному файлу.

Файлы превью находятся в приватном `storage/previews/`, а не в `public/`. Доступ к `/api/attachments/{id}/preview`, `/view` и `/download` каждый раз проверяется по сообщению и исходному посту темы; все ответы `no-store`. Для старых загрузок или потерянного кэша превью автоматически создаются при первом разрешённом запросе. Повторно загружать изображения и менять схему БД **не нужно**. Директория создаётся автоматически; CLI `install`/`migrate` также её подготавливают.

**Windows:** в используемом `php.ini` раскомментируйте `extension=gd`, проверьте `php -m` и перезапустите PHP-сервер. Без GD новые изображения вернут понятную ошибку `image_processing_unavailable`, а не будут приняты без превью. Оригиналы старых изображений можно открыть/скачать и без GD. Доступность декодеров JPEG/PNG/GIF/WebP можно проверить через `php -r "print_r(gd_info());"`.

Предельные габариты — 12000 px на сторону и 40 млн пикселей, но дополнительно действует бюджет памяти PHP: слишком большое для текущего `memory_limit` изображение отклоняется с `413` до декодирования. Повреждённое изображение отклоняется с `422`; сообщение, файлы, решение PoW и таймер публикации откатываются вместе.

## Видео и последние сообщения разделов

Видео загружаются как обычные вложения через выбор, перетаскивание или вставку файлов. Поддержаны **MP4 и WebM** с проверкой MIME и расширения. Плеер находится прямо в сообщении: управление, пауза, перемотка и полноэкранный режим — средствами браузера. Нет автозапуска и предварительной загрузки; видео под спойлером даже не получает `src`, пока его не раскроют. Рядом остаётся скачивание оригинала. Если кодек не поддерживается браузером, можно скачать файл; сервер не перекодирует видео, FFmpeg для работы форума **не требуется**.

Лимиты не изменены: **5 МиБ на файл, 20 МиБ суммарно, до 10 файлов**. Каждый запрос к оригиналу, включая `Range` для перемотки и `HEAD`, проверяет видимость сообщения и исходного поста темы. Передача файла идёт частями, с `no-store`; прямого публичного доступа к `storage/uploads/` нет.

В боковой панели у каждого раздела — до **пяти последних сообщений**, включая темы и ответы, новые ID первыми. Краткие ссылки ведут на нужную страницу темы и якорь ответа. Обычным посетителям выдаются только одобренные сообщения в одобренных темах; персоналу также видны ожидающие проверки с явной пометкой. Отклонённые/удалённые сообщения и ответы в скрытой теме не появляются в этом блоке. Список обновляется при загрузке страницы, отправке ответа и встроенной модерации.

Для этих изменений новая миграция не нужна: используются существующие сообщения и вложения. Обновите HTML, CSS, JS и PHP-файлы вместе, чтобы сервер поддерживал видео и выдавал актуальную CSP.

## Публикация и локальная проверка

1. Анонимы и обычные пользователи отправляют сообщения в `pending`.
2. Пользователи с автоподтверждением, модераторы и администраторы сразу получают `approved`.
3. Модератор/администратор выдаёт и отзывает автоподтверждение. Старую очередь это не меняет.
4. **Ни одна роль не освобождается от PoW и интервала публикации.** Темы и ответы используют общий интервал: 45 с между успешными публикациями анонима, 30 с для аккаунта.
5. Анонимный интервал привязан к HMAC IP, пользовательский — к ID аккаунта, не к cookie. Обновление страницы, новые сессии того же аккаунта или новая анонимная cookie не сбрасывают активный лимит. IP берётся только из `REMOTE_ADDR`.
6. После ожидания пользователь нажимает «Вычислить проверку». Worker подбирает nonce: SHA-256 от `prefix:nonce` должен начинаться с заданного количества нулевых **битов**. Браузер не зависает; вычисление можно отменить. Никаких запросов к Cloudflare/Google/сторонним сервисам.
7. Сервер проверяет решение, срок (5 минут), привязку к сессии/автору и однократность. Задача должна быть выдана после окончания предыдущего интервала; нельзя запасти задачи в других вкладках/сессиях до предыдущего поста. Новая задача заменяет предыдущую в той же сессии.
8. Проверка/занятие интервала/создание темы и сообщения выполняются в одной транзакции с write-lock. Ошибка валидации/раздела не сжигает корректное решение и не запускает интервал. Интервал начинается только после принятой публикации, включая ожидающую модерации.

Сложность по умолчанию **18 бит** (~262 тыс. попыток в среднем, не гарантированное время). `FORBIRDS_POW_DIFFICULTY` задаёт 8–24 бита; 8 предназначено для быстрых тестов, для публичного сервера начинайте с 18 и измеряйте на слабых устройствах. Worker останавливается после 120 с вычислений или истечения задачи. Изменение сложности не меняет 45/30 с на сервере.

**Это не настоящий Cloudflare Turnstile и не доказательство человечности.** Боты тоже умеют решать PoW; GPU и распределённые IP/аккаунты снижают его эффективность. Вычисления расходуют батарею, а анонимы за одним NAT разделяют 45-секундный лимит. Самостоятельная регистрация новых аккаунтов не предотвращает обход пользовательского интервала; для более жёсткой защиты нужны ограничения регистрации/сетевые лимиты и наблюдение за злоупотреблениями. PoW дополняет премодерацию и ограничения запросов, а не заменяет их.

## Видимость и безопасность

- До одобрения сообщения/файлы не видны обычным посетителям, не участвуют в их поиске и счётчиках. Снятие одобрения исходного поста скрывает всю тему и её файлы.
- Автор аккаунта может читать собственные ожидающие сообщения; аноним получает только квитанцию с ID/статусом.
- Права читаются из БД на каждом запросе. Баны и отзыв доверия применяются к существующим сессиям.
- Удаление мягкое; содержимое остаётся для модераторов, API-восстановления нет. Физическая очистка файлов — отдельная будущая задача.
- Текст показывается через `textContent`, не `innerHTML`. Пароли хешируются; запросы параметризованы; все POST требуют CSRF-токен.
- Вложения находятся вне document root и скачиваются только после проверки доступа. Только PNG/GIF/JPEG/WebP могут отображаться inline через защищённый image endpoint. Остальные файлы — исключительно скачивание; исполнения HTML/SVG, распаковки архивов или запуска файлов нет.
- CAPTCHA и cookie не дают надёжного аппаратного HWID; скрытого fingerprinting нет.

## Развёртывание

**Document root строго `public/`, не корень репозитория.** Не создавайте alias для `storage/`, `src/`, `database/`, `.git` или `.tools/`.

- Для встраиваемого dev-preview можно задать `FORBIRDS_ALLOW_EMBED=1`: это убирает запрет iframe только у страниц/ресурсов фронтенда. Не включайте на production (по умолчанию `frame-ancestors 'none'`).
- Production: HTTPS + PHP-FPM + Nginx/Apache. `php -S` только для разработки.
- Все URL приложения направляйте в `public/index.php`: он отдаёт только известные HTML/JS/CSS и изображения фронтенда; `/api/…` возвращает JSON. Необходимые CSP-заголовки уже выставляются.
- Apache 2.4: включите `mod_rewrite`, `AllowOverride FileInfo Options`; `public/.htaccess` содержит правило front controller.
- Nginx: направляйте запросы через PHP-FPM в фиксированный `public/index.php`, сохраняя `REQUEST_URI`. Не разрешайте выполнение произвольных PHP-путей. При отдельной отдаче статических ресурсов сохраните эквивалентные allowlist и CSP (`script-src 'self'; worker-src 'self'`).
- Фронтенд и API на **одном origin**, CORS намеренно не включён. В browser-коде относительные URL; localhost другого сервера не требуется.
- Cookie по умолчанию `Secure`, `HttpOnly`, `SameSite=Lax`. На HTTPS не задавайте `FORBIRDS_SECURE_COOKIE=0`.
- Внешнее хранилище: абсолютный `FORBIRDS_STORAGE=/srv/forbirds-data`. CLI и PHP-FPM должны иметь одинаковую настройку/доступ от одного пользователя ОС. `.env` автоматически не загружается.
- PHP-FPM: `upload_max_filesize=5M`, `post_max_size=21M`, `max_file_uploads=20`. API отклоняет >10 файлов; лимит PHP выше, чтобы 11 файлов не обрезались молча. Лимит тела reverse proxy — 21 МиБ; его собственные ошибки могут не быть JSON.
- За reverse proxy настройте доверенные proxy и реальный IP **в веб-сервере**. Приложение игнорирует входящий `X-Forwarded-For`; иначе анонимный лимит легко подделать. Без настройки все посетители за proxy разделят один IP-лимит.
- SQLite/WAL — один сервер, локальная ФС и умеренная нагрузка. Для высокой параллельности нужна миграция на серверную СУБД.
- Дополнительные IP-лимиты: POST 120/мин, публикации 10/мин, задачи PoW 20/мин, вход 10/15 мин, регистрация 5/час. Сырые IP в БД не пишутся, корзины используют HMAC. Устаревшие задачи удаляются при выдаче новых; корзины публикаций старше суток — при успешной публикации. Access-логи настраиваются отдельно.
- Бэкапы: для работающей SQLite используйте backup API / `sqlite3 ... '.backup ...'`, не копирование одного файла при активном WAL. Сохраняйте `uploads/` и `app.key` (производный кэш `previews/` можно восстановить из оригиналов); для согласованного снимка с файлами остановите запись.

## Проверки

```sh
find src public bin -name '*.php' -exec php -l {} \;
python3 -m unittest discover -s tests -v
node tests/test_hash.cjs
```

Обычные HTTP-тесты не требуют npm. Они запускают отдельный PHP-сервер и временную базу, не трогая рабочий `storage/`. В них сложность снижена до 8 бит; проверки PoW/интервалов не отключаются. Для обычных функциональных сценариев тестовый helper вручную сдвигает время в БД между постами; отдельные тесты проверяют реальные 45/30 с, повторное использование, срок, привязку и параллельные сессии без такого helper. `PHP_BIN=/path/to/php` меняет PHP-команду.

Для полного сценария в Chromium:

```sh
npm ci  # только dev-зависимость playwright-core, не нужна сайту
npx playwright-core install --with-deps chromium
FORBIRDS_BROWSER=1 python3 -m unittest discover -s tests -v
```

Браузерный тест проверяет реальные формы, Worker, файлы/спойлеры, превью PNG/GIF/JPEG/WebP и просмотр оригиналов внутри окна без предзагрузки скрытых картинок, воспроизведение WebM и закрытие просмотрщика по Escape, премодерацию, поиск, свои/чужие профили, изменение описания и аватарки, компактные сообщения, мобильную вёрстку, выдачу доверия и счётчики 45/30 с; внешних запросов не допускается. CI: HTTP на PHP 8.3/8.4/8.5, полный браузерный сценарий на PHP 8.5 и SHA-256/Worker против `node:crypto`.
