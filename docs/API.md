# ForBirds API v1

Все маршруты относительны к origin форума. API использует PHP-сессию в cookie, не Bearer-токены. GET не меняет содержимое форума; все изменения — POST. На маршрутах `/api/…` HTML-разметка не генерируется; страницы `/`, `/index.html`, `/post.html`, `/dashboard.html` обслуживаются отдельно и подключены к API через `public/app.js`. Единственное бинарное исключение — успешное скачивание вложения.

## Общий формат

Успех:

```json
{"data":{"post_id":12,"thread_id":4,"status":"pending"}}
```

Ошибка:

```json
{"error":{"code":"forbidden","message":"Требуются права модератора."}}
```

Статусы: `200` успех, `201` создано, `400` неверный JSON, `401` нужен вход/неверные учётные данные, `403` нет прав/CSRF/бан, `404` нет объекта или он скрыт, `405` неподдерживаемый HTTP-метод, `409` конфликт, `413` превышен размер, `415` неверный Content-Type, `422` неверные поля, `429` лимит запросов (с `Retry-After`), `503` база ещё не установлена. Внутренние ошибки — общий `500`, детали только в серверном error log.

POST принимает `application/json`, `application/x-www-form-urlencoded` и `multipart/form-data`. Для обычной формы всё равно нужен JS или другой HTTP-клиент, который выставит заголовок `X-CSRF-Token`. Булевы значения: JSON `true/false`, числа `1/0` или строки `"1"/"0"`; строки `"true"` и `"false"` не принимаются. Ограничения длины строк указаны **в байтах UTF-8**.

Для **каждого POST**, включая вход, регистрацию и анонимную публикацию:

1. Выполните `GET /api/session`, сохраните cookie и `data.csrf_token`.
2. Передайте токен заголовком `X-CSRF-Token` вместе с той же cookie.
3. После входа, регистрации и выхода обновите токен из ответа — старый перестаёт действовать.

Поля, определяющие права автора (`role`, `auto_approve`, `user_id`, `status`), при публикации/регистрации клиент назначить не может. Права и статус вычисляются на сервере.

### Пагинация

Списки тем, ответов, своих сообщений, очереди и аудита:

```json
{"data":{"items":[],"page":1,"limit":20,"has_more":false}}
```

Query-параметры: `page` от 1, `limit` от 1 до 100 (большее значение ограничивается до 100). Списки разделов и публичный профиль не пагинируются.

## Сессия и аккаунты

| Метод | Маршрут | Поля / результат |
|---|---|---|
| GET | `/api/session` | `csrf_token`, `user` или `null` |
| POST | `/api/auth/register` | `username`, `password`; возвращает пользователя и новый CSRF, сразу выполняет вход |
| POST | `/api/auth/login` | `username`, `password`; возвращает пользователя и новый CSRF |
| POST | `/api/auth/logout` | `{}`; сбрасывает вход и возвращает новый CSRF |
| GET | `/api/users/{id}` | Профиль без хеша пароля. `auto_approve` виден только самому пользователю и персоналу |
| GET | `/api/me/posts` | Собственные сообщения, включая ожидающие, отклонённые и мягко удалённые; нужен вход |

Имя: 3–32 латинских буквы, цифры или `_`, уникальность без учёта регистра ASCII. Пароль: 12–72 байта, без NUL, хранится только хеш. Обрезки пробелов у пароля нет. Email и восстановление пароля пока не реализованы.

Поля пользователя в своей сессии: `id`, `username`, `role`, `auto_approve`, `is_banned`, `created_at`. Булевы поля из SQLite возвращаются как `0/1`. Время в UTC, ISO 8601.

## Разделы

| Метод | Маршрут | Доступ |
|---|---|---|
| GET | `/api/sections` | Все |
| POST | `/api/sections` | Администратор |
| POST | `/api/sections/{id}/settings` | Администратор |

Создание:

```json
{"slug":"general","title":"Общий раздел","description":"Обсуждение форума"}
```

`slug`: 1–64 байта, строчные латинские буквы/цифры с одиночными дефисами между группами. `title`: 1–200, `description`: 0–4000, необязательно.

Настройки: любое подмножество `title`, `description`, `is_archived`. `slug` после создания не меняется. Архивный раздел доступен для чтения, обычные авторы не могут создавать там темы и ответы; персонал может.

## Локальная хэш-капча и интервалы

Проверка обязательна для **каждой темы и ответа, для всех ролей**. Это локальный proof-of-work, не Cloudflare Turnstile и не доказательство человечности. Создание разделов, вход и действия модератора не требуют PoW (но требуют CSRF/прав и ограничены по частоте).

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/posting-status` | `interval_seconds`, `retry_after`, `next_allowed_at` (Unix UTC или 0), `pow_required:true` |
| POST | `/api/pow/challenge` | Выдать одноразовую задачу, тело `{}`, нужен CSRF |

Интервал между принятыми сообщениями: **45 секунд для анонимов, 30 секунд для всех аккаунтов**, включая доверенных, модераторов и администраторов. Темы и ответы разделяют один лимит. Анонимный ключ — HMAC `REMOTE_ADDR`, пользовательский — HMAC ID аккаунта. Новая cookie/вкладка/повторный вход не сбрасывают активный интервал; анонимы за одним IP разделяют лимит. Передача `X-Forwarded-For` клиентом его не меняет.

Пока интервал не окончен, выдача задач и публикация возвращают `429`, `error.code: "posting_cooldown"`, `error.retry_after` и HTTP `Retry-After` с оставшимися секундами. Отсчёт начинается после успешного принятия сообщения, даже если оно ожидает модерации.

Задача:

```json
{"data":{"id":"32-hex-characters","prefix":"64-hex-characters","difficulty":18,"expires_at":1795694400,"algorithm":"sha256","format":"prefix:nonce","interval_seconds":45}}
```

Строки ID/prefix в этом примере описательные; реальные значения — случайный lowercase hex. Решение — десятичная строка `nonce` без ведущих нулей (кроме `"0"`), до 16 цифр. Нужно подобрать её так, чтобы SHA-256 от **UTF-8 строки `prefix + ":" + nonce`** начинался с `difficulty` нулевых **битов**, не hex-символов. Это проверяет PHP, а не доверяет флагу от клиента. Worker/реализация SHA-256 уже находятся в `public/pow-worker.js` и `public/sha256.js`.

Передавайте при создании темы/ответа в JSON или FormData:

```json
{"pow_id":"<id задачи>","pow_nonce":"<найденное число>"}
```

Особенности:

- Срок задачи 300 с. Новая задача заменяет предыдущую для той же сессии/автора; разные вкладки одной сессии могут сделать старое решение неактуальным.
- Привязка к PHP-сессии и субъекту лимита. Вход/выход, другая сессия или другой анонимный IP делают чужое решение непригодным.
- Решение одноразовое; его потребление, занятие интервала и запись сообщения атомарны. Ошибка публикации откатывает их вместе.
- Задача должна быть выдана после окончания предыдущего интервала. Предварительно запасённые в других сессиях задачи нельзя использовать после следующего сообщения.
- Ошибки `422`: `pow_required` (нет/неверный формат полей), `pow_invalid` (неверный хэш), `pow_expired` (срок, повторное использование, неверная привязка или устаревшая задача).
- Задачи: до 20/мин на IP, дополнительно к общим лимитам POST/публикаций. CSRF требуется и анонимам.
- `FORBIRDS_POW_DIFFICULTY` на сервере: 8–24 бита, по умолчанию 18. Клиент не выбирает сложность. Время решения вероятностное и зависит от процессора; мощные боты тоже могут решать задачи.

## Темы и ответы

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/threads` | Только публичные темы |
| GET | `/api/threads/{id}` | Тема, исходный `post` и пагинированные `replies` |
| GET | `/api/posts/{id}` | Одно доступное сообщение с вложениями |
| POST | `/api/threads` | Создать тему и её исходное сообщение атомарно |
| POST | `/api/threads/{id}/replies` | Создать ответ без заголовка |
| POST | `/api/threads/{id}/settings` | Настройки темы; модератор/администратор |

Создание темы:

```json
{"section_id":1,"title":"Первая тема","body":"Текст сообщения","pow_id":"<id>","pow_nonce":"<решение>"}
```

Ответ:

```json
{"body":"Текст ответа","pow_id":"<id>","pow_nonce":"<решение>"}
```

`title`: 1–200, `body`: 1–50000 байт, пустые/пробельные значения не допускаются. Текст — **обычный текст**, не HTML и не BBCode. На фронтенде используйте `textContent` (и CSS `white-space: pre-wrap`), не `innerHTML`.

Ответ на создание: `post_id`, `thread_id`, `status`. `№` в интерфейсе — `post_id`, глобально уникальный для тем и ответов. Автоматические статусы:

| Автор | Статус |
|---|---|
| Аноним / обычный пользователь | `pending` |
| Пользователь с `auto_approve=1` | `approved` |
| Модератор / администратор | `approved` |

Клиент не может запросить одобрение собственным полем `status`. Автор аккаунта видит свои `pending`-публикации в `/api/me/posts` и по ID, но они не появляются в публичном списке. Анонимное ожидающее сообщение доступно только персоналу, даже в сессии отправителя.

### Главная, новости, поиск

Фильтры `GET /api/threads` можно совмещать:

- `?section_id=1` — раздел;
- `?featured=1` — главная;
- `?news=1` — новости/обновления;
- `?q=слово` — поиск подстроки в заголовке или **одобренных** сообщениях, без учёта регистра Unicode; 2–200 байт;
- `?limit=20&page=2` — пагинация.

Темы сортируются от новых к старым по ID, ответы — от старых к новым. Поднятия темы новым ответом пока нет. `reply_count` считает только одобренные ответы. Одобрение ответа не делает публичной тему со скрытым исходным постом. Тема с удалённым/отклонённым/ожидающим исходным постом не появляется в публичной выдаче.

При создании темы персонал может передать `is_news`, `is_featured`. Обычный пользователь получает `403`, если пытается включить эти отметки.

Настройки темы: любое подмножество `is_locked`, `is_news`, `is_featured`. В закрытую тему обычные авторы не отвечают, персонал может. Эти настройки не заменяют одобрение исходного поста.

## Вложения

При создании темы или ответа вместо JSON отправьте `FormData`:

- обычные поля `section_id`, `title`, `body` (для ответа только `body`), а также `pow_id` и `pow_nonce`;
- до 10 файлов в `files[]`;
- необязательный массив `spoilers[]` — индексы файлов, начиная с 0.

Лимиты: 5 МиБ на файл, 20 МиБ суммарно. Разрешены JPG/JPEG, PNG, GIF, WebP, TXT, PDF и ZIP. Проверяются MIME через `fileinfo` и соответствие расширению. Изображения дополнительно проверяются по заголовку и габаритам: каждая сторона не более 12000 px и не более 40 млн пикселей. Исполняемые файлы, HTML и SVG не принимаются. Архивы не распаковываются; наличие допустимого MIME не означает отсутствие вредоносного содержимого.

`GET /api/posts/{id}` возвращает `attachments`:

```json
[{"id":3,"original_name":"photo.jpg","mime_type":"image/jpeg","byte_size":1024,"spoiler":1,"download_url":"/api/attachments/3/download"}]
```

`GET /api/attachments/{id}/download` проверяет доступ **к сообщению и исходному посту темы**. До одобрения файл доступен только персоналу и зарегистрированному автору ожидающего сообщения. После снятия одобрения доступ снова закрывается. Физический путь, случайное имя файла на диске и прямой публичный URL не раскрываются.

Файлы всегда выдаются с `Content-Disposition: attachment`, `application/octet-stream`, `nosniff` и `no-store`. Автоматических превью пока нет. `spoiler` — метаданные для будущего интерфейса, не отдельное право доступа. Редактирования публикаций и дозагрузки файлов после создания пока нет.

## Модерация

| Метод | Маршрут | Доступ |
|---|---|---|
| GET | `/api/moderation/queue` | Модератор/администратор |
| GET | `/api/moderation/audit` | Модератор/администратор |
| POST | `/api/posts/{id}/moderate` | Модератор/администратор |
| POST | `/api/users/{id}/trust` | Модератор/администратор |
| POST | `/api/users/{id}/ban` | Модератор/администратор |
| POST | `/api/users/{id}/role` | Только администратор |

Модерация поста:

```json
{"action":"approve","reason":"Проверено"}
```

Действия:

- `approve` → `approved`;
- `unapprove` → `pending`, убрать из публичного доступа;
- `reject` → `rejected`;
- `delete` → `deleted`, без API-восстановления. Файлы не удаляются физически, но доступ к ним закрывается.

`reason` необязателен, до 1000 байт. Переходы между `pending`, `approved`, `rejected` разрешены; `deleted` — конечный статус. Одобрение происходит для конкретного сообщения, а не всей темы.

Автоподтверждение и бан:

```json
{"enabled":true,"reason":"Доверенный участник"}
```

Отключение: `enabled:false`. Автоподтверждение действует только на **будущие** сообщения, не меняет старую очередь. Блокировка запрещает вход и любые POST, кроме выхода, в том числе для уже открытой сессии. Ранее одобренные сообщения забаненного остаются опубликованными; в сообщении/профиле есть признак бана для отображения интерфейсом.

Модератор управляет только обычными пользователями. Администратор также может управлять модераторами. Нельзя через эти маршруты менять самого себя или администратора. Назначение роли:

```json
{"role":"moderator","reason":"Назначение модератора"}
```

Допустимы `user` и `moderator`. Администратор создаётся только локальной CLI-командой, повысить себя через регистрацию/POST невозможно. Роль модератора сама даёт немедленную публикацию; при понижении отдельный ранее выданный `auto_approve` сохраняется (при необходимости отзовите отдельно).

Очередь содержит только `pending`, порядок от старых к новым. Для просмотра вложений сообщения из очереди используйте `/api/posts/{id}`. Персонал также может читать отклонённые и мягко удалённые сообщения по ID для разбирательств.

Изменения статусов, доверия, банов, ролей, разделов и настроек тем пишутся в `audit_log` в одной транзакции с изменением. Аудит доступен только персоналу; включает исполнителя, действие, объект, время и подробности.

## Пример подключения фронтенда

Рабочий интерфейс уже использует отдельный `public/app.js`, не PHP-шаблоны. Ниже сокращённый пример HTTP-клиента; вычисление PoW выполняйте Worker-ом после проверки `/posting-status`:

```js
let csrf;

async function api(path, { method = 'GET', body } = {}) {
  const headers = {};
  if (method === 'POST') headers['X-CSRF-Token'] = csrf;
  if (body !== undefined && !(body instanceof FormData)) {
    headers['Content-Type'] = 'application/json';
    body = JSON.stringify(body);
  }
  const response = await fetch(`/api${path}`, {
    method, headers, body, credentials: 'same-origin'
  });
  const result = await response.json();
  if (!response.ok) throw new Error(result.error.message);
  if (result.data?.csrf_token) csrf = result.data.csrf_token;
  return result.data;
}

function solveChallenge(challenge) {
  return new Promise((resolve, reject) => {
    const worker = new Worker('/pow-worker.js');
    worker.onmessage = ({ data }) => {
      if (data.type === 'solved') { worker.terminate(); resolve(data.nonce); }
      else if (data.type === 'error') { worker.terminate(); reject(new Error(data.message)); }
    };
    worker.onerror = () => { worker.terminate(); reject(new Error('Ошибка Worker')); };
    worker.postMessage(challenge);
  });
}

await api('/session');
await api('/auth/login', {
  method: 'POST',
  body: { username: 'admin', password: passwordInput.value }
});

const section = await api('/sections', {
  method: 'POST', body: { slug: 'general', title: 'Общий раздел' }
});

// solveChallenge запускает /pow-worker.js и возвращает nonce из сообщения type=solved.
const challenge = await api('/pow/challenge', { method: 'POST', body: {} });
const nonce = await solveChallenge(challenge);
const result = await api('/threads', {
  method: 'POST',
  body: { section_id: section.id, title: 'Привет', body: 'Первая тема', pow_id: challenge.id, pow_nonce: nonce }
});

// Загрузка выполняется ОДНИМ запросом с созданием сообщения.
// Это СЛЕДУЮЩАЯ публикация: дождитесь interval, получите НОВУЮ задачу и решите её.
const status = await api('/posting-status');
await new Promise(resolve => setTimeout(resolve, status.retry_after * 1000));
const fileChallenge = await api('/pow/challenge', { method: 'POST', body: {} });
const fileNonce = await solveChallenge(fileChallenge);
const form = new FormData();
form.append('pow_id', fileChallenge.id);
form.append('pow_nonce', fileNonce);
form.append('section_id', section.id);
form.append('title', 'Тема с файлом');
form.append('body', 'Текст');
form.append('files[]', fileInput.files[0]);
form.append('spoilers[]', '0');
await api('/threads', { method: 'POST', body: form });
// Content-Type для FormData браузер выставляет сам вместе с boundary.
```

В реальном интерфейсе перехватывайте ошибки, не храните пароль после входа, показывайте сообщение о премодерации при `status === 'pending'`. Ссылки на скачивание берите из `download_url`. Нельзя вызывать `response.json()` для успешного бинарного скачивания — используйте обычную ссылку или `response.blob()`.
