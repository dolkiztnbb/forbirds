# Баннеры и ответы в реальном времени

## Баннеры

Поместите изображения в `public/static/banners`. Файлов, добавленных в другой ветке,
здесь автоматически не появляется: их нужно перенести обычным merge/копированием.
Поддерживаются PNG, JPEG, GIF, WebP, AVIF; до 10 МиБ и 8000×4000, максимум 256
изображений, без SVG, символических ссылок и вложенных каталогов. Имена с пробелами
и UTF-8 поддерживаются. Содержимое проверяется, одного расширения недостаточно.

`GET /api/banner` возвращает картинку и время следующей серверной минуты. Сервер
берёт SHA-256 от номера минуты и номера попытки; если выпала предыдущая картинка,
хэширует снова (с ограничением попыток и гарантированным выбором другой картинки).
Выбор общий для посетителей и сохраняется в приватном storage. Внутри минуты он
стабилен; при одном изображении повтор неизбежен. Пустой каталог использует прежний
`/static/banner.png`. Таймера в интерфейсе нет — только изображение, ссылка на главную.

## Live-ответы (SSE, PHP)

На странице темы браузер открывает `GET /api/threads/{id}/events` (EventSource).
Это **не обновление страницы** и не периодический GET темы: сервер присылает
версию при подключении и затем только при изменении доступного этому зрителю
снимка. Клиент запрашивает JSON темы при новой версии, смене прав или окончательном
отказе соединения (чтобы убрать уже недоступную тему). Сервер проверяет
SQLite `data_version` раз в 500 мс; без изменений не собирает снимок заново.
Новые ответы обычно появляются в пределах секунды плюс время запроса/сети.

- Премодерация не обходится: гость видит опубликованное, автор — также свои
  ожидающие проверки, персонал — доступные ему сообщения. В SSE нет тела поста,
  IP, отпечатка браузера или иных сырых данных — только хэши версий/области доступа.
- Режим показа использует `public_view=1` для потока и штатное понижение прав
  в обычном GET. Параметр может только **уменьшать**, но не повышать права.
- Сессия не заблокирована на время потока; смена роли, бан, выход или отзыв
  приватного режима вызывают сброс локального представления и перечитывание прав.
- Изменения видимости, удаления, переносы и реакции также меняют снимок.
- Неизменённые DOM-узлы сохраняются: черновик, фокус в нём и проигрывание неизменённых
  вложений не сбрасываются. Скролл принудительно не перемещается.
- Обычная пагинация по 20 ответов остаётся. Дополнительно отображается ограниченный
  хвост из 20 последних видимых ответов за пределами текущей страницы; для более
  старых сообщений используются ссылки страниц. Это не бесконечно растущий DOM.
- Поток живёт до 20 с, heartbeat каждые 5 с; EventSource переподключается сам
  и сверяет актуальную версию, включая пропущенные во время разрыва изменения.
  Скрытые вкладки закрывают поток. При недоступности live есть кнопка повторного
  подключения, **без fallback на таймерный опрос**. Старые браузеры без EventSource
  сохраняют обычное чтение/публикацию.

## Сервер

SSE занимает один PHP worker на время подключения. Значение по умолчанию
`FORBIRDS_LIVE_MAX_STREAMS=2` ограничивает **общее** количество потоков для storage;
лишние получают HTTP 204, что останавливает автоматические повторы браузера.
Увеличивайте лимит только вместе с пулом PHP-FPM, оставляя достаточно свободных
workers для чтения, вложений, входа и публикации. Например, для лимита 16 нужен пул
существенно больше 16 workers. Для большого форума лучше выделенный событийный
сервис, а не сотни блокирующих PHP-потоков.

Для локального Linux/macOS используйте многопроцессный сервер:

```sh
PHP_CLI_SERVER_WORKERS=4 FORBIRDS_SECURE_COOKIE=0 php \
  -S 0.0.0.0:8080 -t public public/router.php
```

Один worker `php -S` будет блокировать остальные запросы на время SSE. В таком
окружении (также Windows) отключите live: `FORBIRDS_LIVE_ENABLED=0`.

На production используйте PHP-FPM с параллельными workers и обычный маршрут в
`public/index.php`. Для SSE отключите буферизацию и сжатие у прокси/CDN, оставьте
read/idle timeout больше 25 секунд. Ответ уже содержит `X-Accel-Buffering: no`;
не игнорируйте этот заголовок в Nginx. Например, в существующем FastCGI location:

```nginx
fastcgi_read_timeout 35s;
# Если конфигурация игнорирует X-Accel-Buffering, уберите такое игнорирование
# или отключите fastcgi_buffering для маршрута /api/threads/{id}/events.
```

Для Apache/mod_deflate и внешних прокси исключите `text/event-stream` из сжатия
и буферизации. Проверка: `curl -N https://your-host/api/threads/1/events` должна
сразу показать `event: change`, а не выдать всё одним блоком через 20 секунд.

Live не удерживает shared-lock обновлятора; при появлении maintenance-маркера
сервер закрывает поток с событием обслуживания. Баннеры и новые модули поставляются
локально, Node.js/WebSocket-сервер для работы не нужен. Миграций БД нет.

## Проверки

`npm test` включает unit-тесты EventSource-клиента (нет polling, версии,
переподключение, смена прав, свёртывание серии событий и очистка listeners).
`python3 -m unittest discover -s tests -v` включает каталог/ротацию баннеров,
видимость live-снимков и нативные SSE-тесты с конкурентными PHP workers:
премодерация, отзыв роли, публичный режим, свободная сессия, лимит потоков,
удаление темы и совместимость с maintenance. PHP-WASM пропускает нативные
SSE-тесты: он не моделирует workers и файловые блокировки production PHP.

## Кэш постов и тем

`GET /api/posts/{id}`, `GET /api/threads` и `GET /api/threads/{id}` возвращают
персональный ETag. При повторном запросе с `If-None-Match` неизменившийся JSON
не передаётся: сервер отвечает HTTP 304. Права и текущая видимость проверяются
**перед** сравнением ETag; удалённый/скрытый пост по-прежнему возвращает 404,
а не старое содержимое. ETag зависит от JSON, сессии, языка и режима показа.
Общий прокси-кэш запрещён (`private`), повторное использование требует проверки.

Клиент хранит максимум 80 JSON-ответов и примерно 4 МиБ текста в памяти вкладки,
вытесняя давно не использованные записи. Одинаковые параллельные GET объединяются.
Ключ разделяет URL/пагинацию, пользователя, язык и режим показа. Кэш очищается
до и после POST, при сбросе прав live и уходе со страницы. В localStorage,
IndexedDB и service worker посты не сохраняются; fetch использует `no-store`,
чтобы не полагаться на неуправляемое повторное использование HTTP-кэша браузера.
При ошибке сети старый пост не выдаётся вместо ошибки. Сессия, идентификаторы,
модераторские журналы, файлы и SSE-потоки этим JSON-кэшем не кэшируются.

Это экономия повторной передачи тела ответа, а не отмена проверки
прав/SQL на сервере. У темы по-прежнему нет периодического опроса: SSE сообщает
об изменениях, и клиент перепроверяет JSON только по событию/действию пользователя.
